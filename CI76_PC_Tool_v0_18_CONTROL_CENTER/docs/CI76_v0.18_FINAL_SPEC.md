# MOTECK CI76 Control Center — v0.18 Final Development Specification

**Status:** APPROVED FOR CODEX IMPLEMENTATION (UI / UX scope only)  
**Date:** 2026-11-05  
**Source baseline:** `CI76_PC_Tool_v0_17_CONTROL_CENTER`  
**Target:** Windows 10/11 · Python 3.12 · PySide6 6.7+ · pyserial 3.5+  
**UART:** Protocol 251110 · 115200 baud · 8N1 · Device Code `0x0B01`  
**Confirmed design decisions:** Midnight Tech Blue theme; remember last successful COM port and offer an **opt-in** Auto Connect switch; first page is compact single-page, scrolling only when necessary.

## 0. Implementation contract / non-negotiables

1. **Do not modify STM32 firmware, protocol commands, CRC/checksum, packet encoding, field units, MCU parameters, or Flash logic.** This is the PC Tool v0.18 UI refinement, not an MCU revision.
2. Preserve existing functions and safety checks: parameter read/write, `.config`, 0–8 A current limit range, two-page independent editor behavior, 50–1500 ms monitoring, fault flags, operating time, Hall/POT selection, learning, diagnoses, event Log, UART mode, start/stop, and legacy 2-second PC motion limit. Keep interlocks and existing overload threshold validation.
3. **Do not auto-send parameter write, learning, motor motion, UART MODE ON, or fault-clear** during application startup, automatic port selection, automatic connection, or tab switching.
4. Existing v0.17 default device identity verification uses Device Code `0x0B01` (`main.py`); retain that check. Do not require firmware *version* to equal `0x0B01` for routine identity, because firmware can change.
5. Refactor incrementally. In particular, do not replace or casually redesign `protocol.py`, `transport.py`, `worker.py`, `motion.py`, `monitoring.py`, `diagnostics.py`, or `eventlog.py`. Only touch them if necessary to support UI state integration, with separate tests and a written reason.
6. If a request conflicts with hardware safety or the current protocol, preserve the existing behavior, report the difference, and do not silently simulate success.
7. This specification authorizes **code changes** only when run inside Codex against the included project; preparing this document has not changed the application or firmware.

## 4. COM port connection — approved behavior

### 4.1 UX

Single compact card contains: Port selector (name + COM + useful USB label), Scan, Connect/Disconnect, opt-in `啟動時自動連線` checkbox, and persistent connection state indicator.

**Auto Connect defaults OFF.** User may enable it in UI; settings persist with `QSettings("MOTECK", "CI76ControlCenter")` or an equivalent Qt-native persistent settings mechanism.

Persist only safe preferences (auto-connect enabled, last successfully confirmed port, optional serial-number/VID/PID/HWID, monitor interval, window geometry if appropriate). **Never persist or auto-replay motor commands or parameter-write intents**.

### 4.2 Startup state machine

1. Start worker thread and GUI; enumerate serial ports asynchronously or fast enough not to block UI.
2. Match last successfully used device. Prefer *unique* USB serial number plus VID/PID; otherwise exact prior COM + consistent HWID/description where possible. Do not assume COM number alone proves identity.
3. If unique match, preselect it regardless of Auto Connect setting.
4. Only when Auto Connect is ON and a unique safe match exists, request one connection attempt using the existing `SerialWorker` path; **never** brute-force commands to all serial ports.
5. After opening port, perform read-only CI76 identity query; mark device VERIFIED only if returned Device Code matches `0x0B01`.
6. If identity mismatch or timeout, close that serial connection, show a precise error and wait for manual selection; no writes or motor action.
7. If port missing, ambiguous or busy, show a nonblocking message and stay disconnected.
8. Save/update `last successful port` only **after** a valid CI76 identity response.
9. Preserve manual Disconnect; user-initiated disconnect must not immediately auto-reconnect during the same run. Prevent duplicate connection attempts/retry storms; handle USB removal gracefully.

### 4.3 UI states

`DISCONNECTED`, `CONNECTING`, `CONNECTED—VERIFYING`, `CI76 VERIFIED`, `PORT BUSY`, `IDENTITY MISMATCH`, `TIMEOUT / REMOVED`. Disable write functions unless identity verified and existing safeguards satisfied. Lost connection marks live measurements stale instead of displaying an apparently new value.

**Acceptance:** no motor movement, change to UART MODE, parameter write or learning caused by automatic connection.

## 5. Page 1 — CONTROL / 參數設定 (compact-first)

### 5.1 Fixed upper area

1. Brand header (compact)
2. COM card (single line if width allows)
3. Utility bar: Read Device Info | Read All | Read Status | one global Auto Monitor checkbox | monitor cycle | actual refresh value | .config Import/Export (may live in header toolbar)
4. **Main control strip, one row in this order:** UART MODE | Speed 0–100% | Extend | Retract | **STOP (Esc)** | **開始行程學習** | **取消學習**.
5. Maintenance strip (condensed): 擷取診斷 | 清除錯誤 | Log 資料夾 | one-line safety/status summary. Longer explanation available as detail, not a large full-width always-visible warning.

Important: STOP remains prominent and reachable. Do not weaken, circumvent or infer firmware safety behavior. Learning is an actual motor-moving action and stays behind existing confirmation and readiness checks. `Esc` continues to call the existing STOP function, not a new shortcut implementation that silently changes semantics.

### 5.2 Content grid

Three columns, with consistent card headers and text alignments:

- **Left:** Voltage protection, Regeneration protection, Current parameters (0–8 A quick slider).
- **Middle:** Speed parameters, Position parameters.
- **Right:** Device Info and Sensor settings, Live current and position, Runtime, Nine fault flags.

Keep first page current parameter behavior: editing the slider/numbers is **local draft**, no UART write until user clicks `寫入（暫存）` and existing confirmation/readback succeeds.

Keep position software limits 0–100% with firmware-compatible step size. Preserve all parameter fields, including overcurrent threshold and duration, and per-group Read/Write.

### 5.3 Layout requirements

- At **1920×1080 with Windows 125% scaling**, target full first-page view without vertical scrolling when UART log is collapsed.
- At **1366×768 with 100% scaling**, allow a **local content scrollbar** only where genuinely needed; no clipping, overlay, hidden action buttons, or forced text overlap.
- Do not use absolute coordinates; use Qt layouts, stretch factors, size policies, minimum content widths, compact group margins and responsive wrap when needed.
- Log stays collapsed by default, expandable on demand; expand/collapse does not break the core layout.

## 6. Page 2 — TUNING / 電流展示

Three clear functional zones only:

1. **Current Limit Control**: 0.00–8.00 A slider + editable number; send via existing UART current-limit command on slider change with existing debounce/coalescing and readback confirmation; display `Desired`, `Sending`, `MCU Confirmed`, `Failed` states. `立即套用/重試` and `還原展示前設定` remain functional.
2. **Actual Motor Current**: read-only current (UART `0x10`), large numerical A label, horizontal bar, optional pointer gauge. View switch: `Bar + Gauge`, `Bar only`, `Gauge only`. Do not claim measured thrust or measured RPM. Meter gauge decoration must never show hover rectangle artifact.
3. **Compact Status Summary**: Motor Status, COM Link, Sensor, Faults, and actual current polling interval.

- No duplicate Demo Auto Monitor switch. Use the single global Auto Monitor control.
- No Demo motor Extend/Retract/Stop controls; v0.17 second page was already simplified to current tuning and telemetry. Do not reintroduce them.
- Remove the separate `>2 A` confirm/checkbox or flow, but retain existing MCU overcurrent threshold validation. User states 0 A is supported in newer firmware: permit 0 A as the current project does; readback still required. **Do not represent 0 A as an emergency stop.**
- **Cross-tab independence:** first page draft editing cannot auto-send; second page auto-sends. After a successful MCU write/readback, update displayed confirmed values in both pages without overwriting an unsubmitted first-page user draft. Switching tabs must not replay stale pending Demo targets or revert hardware settings.
- Keep current-priority 50 ms *target* monitoring; actual refresh interval is displayed and may be longer due to UART transaction scheduling. Preserve background telemetry and nonblocking GUI.

## 7. Diagnostics and safety behavior (unchanged by UI rewrite)

- Keep nine fault flags, `0x16` counters, `0x17` current flags, runtime, reset-runtime request, `.config`, and PC-side event Log / diagnostic export.
- For invalid, stale or unavailable data, show `—`, `UNKNOWN`, `READ FAILED` or age of last success, never an inaccurate green checkmark.
- v0.17 legacy firmware `0x0B01` lacks proven MCU UART-disconnect stop protection; existing PC-side 2-second limit and other safeguards **must remain**. I1 cannot be described as an emergency stop.
- Previously identified Hall/POT false-learning success bug is an **MCU firmware issue OUT OF SCOPE** for v0.18. Do not edit `firmware_review_only/` or claim UI changes repair it.
- If a parameter is acknowledged but Flash persistence is unverified, keep the warning: `寫入（暫存）` is not proof of nonvolatile save.

## 8. Implementation guidance (pragmatic modularization)

Prefer extracting `theme.py`, `ui_components.py` (or a small `ui/` package), `settings_store.py` to reduce the size of `main.py` while leaving known-good event handlers and UART code intact. Splitting is optional if it creates risk; stable functionality is more important than a wholesale rewrite.

- Do not modify `main.py` by blind global string replacements. Use narrow, reviewable edits.
- Establish consistent object names / tokens; avoid contradictory page-local hardcoded QSS from v0.17.
- Keep UI control state synchronized with `connected`, `identity_verified`, active operation, and worker signals.
- Auto-connect uses the same existing connection path as manual connect, not a second serial driver.
- No blocking serial I/O in the Qt UI thread; no overlapping serial requests.
- New dialogs and controls must use functional event handlers and clear Chinese labels, English secondary technical captions where helpful.
