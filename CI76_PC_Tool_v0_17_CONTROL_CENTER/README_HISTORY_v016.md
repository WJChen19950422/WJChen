# MOTECK CI76 PC Tool v0.15 HUD LAB

Windows / Python 3.12 / Protocol 251110。沿用 v0.13 的 STM32 `0x0B01` 既有協定；**本版沒有修改 CI76 韌體**。本版以第二頁 UI 瘦身與監控排程改善為主。

## v0.14 基礎功能（本版保留）

1. **第二頁僅保留兩個主要展示區**：
   - **Demo 限流控制**：0.00～8.00 A，數字欄位、滑桿、MCU 讀回狀態、高電流操作確認、手動套用／還原展示前限流。
   - **實際馬達電流**：即時數值、橫條與指針儀表，三種顯示方式（橫條＋儀表／單獨橫條／單獨儀表）。
   - 移除第二頁的展示模式選擇、速度設定及 PC UART 伸出／縮回／停止控制列；**第一頁原有的控制與行程學習功能保留**。
2. **統一自動監控**：只使用視窗上方的「自動監控」與更新週期下拉選單。取消第二頁額外的「Demo 自動快速監控」開關；切換分頁不再擅自改變是否監控或更新週期。
3. **電流優先輪詢**：在 Demo 頁且已勾選「自動監控」時，工作執行緒每輪先查 `0x10` 馬達電流，最多附帶一個背景查詢；兩個背景查詢至少相隔 220 ms。其他狀態仍會輪流讀取，不會每輪連發 6 條指令。
4. **刷新資訊更準確**：上方「電流實際」和 Demo 裡的「電流實際刷新」都使用連續兩筆**成功的電流資料**在 PC 端收到的間隔，不再以「整輪監控結束時間」冒充電流資料更新率。

## 為何可能出現 500 ms？

- v0.13 在 50 ms 定時器下，一輪自動監控最多要讀 `0x10`、`0x11`、`0x12`、`0x13`、`0x17`、`0x14`；它們是逐個請求／等待回覆。每條查詢的自動監控等待逾時最多 120 ms，一輪很容易拖到數百 ms。
- Demo 滑桿自動寫入會先讀取韌體版本、設備、旗標、狀態、現有電流參數，再發 `0x06` 並用 `0x19` 讀回；整個過程會暫停輪詢，因此調整滑桿期間仍可能見到較長刷新間隔。
- USB-to-UART (如 CP210x) 延遲、Windows 排程、韌體處理時間與通訊錯誤也可能造成延後。**50 ms 是目標而非保證；未做 CI76 實板速度測試**。

## 兩頁限流邏輯維持不變

- **第一頁**：調整欄位後必須按「電流 → 寫入（暫存）」才送出。
- **第二頁**：拖動滑桿後約每 250 ms 合併最新設定，嘗試送出 UART `0x06`，再以 `0x19` 確認。
- 控制器只有一組限流值。以最後一次成功讀回的 MCU 數值為準；拖動第二頁滑桿時不會直接改寫第一頁的輸入欄位。
- 第二頁有「還原展示前限流」按鈕；歸還原始值前須先確認停止。其他電流參數（過載門檻與時間）維持不變。

## 在 Windows 啟動

雙擊 `START_PC_TOOL.bat`，或在解壓縮資料夾 PowerShell 執行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

不連接硬體也可做版面檢查：

```powershell
.\.venv\Scripts\python.exe tools\layout_smoke.py
```

會輸出 `CI76_v0_15_page1.png`、`CI76_v0_15_hud.png`。

## 建議實板驗證

1. 先用 v0.15 開啟 HUD Demo 頁，勾上方「自動監控」、選 **50 ms**。不動滑桿時連續觀察 30 秒，記下「電流實際刷新」常見值及最大值。
2. 保持相同監控狀態拖動 Demo 限流，觀察偶發變慢是否恰好發生於 `0x06` 寫入／`0x19` 讀回期間。
3. 再切到第一頁觀察原本模式的延遲，確認切頁前後上方「自動監控」及所選週期完全不變。
4. 以「讀取全部參數」再次確認電流及過載保護參數沒有被意外改動。

## 安全提醒

- **限流值不是恆定電流輸出指令**，也不代表推桿實際推力；不應以手或身體阻擋推桿體驗力道。
- Demo 顯示 0～8 A 僅代表 PC Tool 設定範圍，並不保證硬體額定電流或安全。超過 2 A 仍需要明確的內部測試確認。
- 所有參數寫入都可能影響馬達和保護，MCU RAM 的 ACK／讀回不保證 Flash 永久保存。
- 第一頁仍含有 LAB 馬達控制功能。FW `0x0B01` 不具 UART 失聯自停保護，舊版的 PC 端 2 秒測試限制仍保留，請使用獨立硬體斷電裝置，**不可交付客戶作為安全控制**。
- 已通過自動化純軟體測試；Windows GUI 與實際 CI76 串列通訊／刷新速度仍需現場確認。

## v0.15 HUD 介面（參考照片風格）

本版新增黑底青綠的 cockpit HUD 展示介面（第二頁），保留第一頁原本已驗證的參數設定畫面。
左側顯示 **UART 實際馬達電流**；右側顯示 **限流目標值**，兩者不代表相同量；中間馬達圖為示意，不會虛構轉速、扭矩或位置。
高電流操作仍受既有確認限制。詳見 `CHANGELOG_v015.md` 與 `LEARNING_VALIDATION_ANALYSIS.md`。

> 重要：目前韌體未接 Hall/POT 仍可能誤判學習完成，請勿把 MCU 清除 0x20 或 PC Tool 顯示學習結束視為有效行程校正；需修補 MCU 驗證邏輯並做實板測試。
