# CI76 客戶端離線事件紀錄：建議的後續 MCU 韌體需求

本文件為需求設計草案，**未實作到提供的韌體**。目前 `0x16` 回傳四個 16-bit 累積錯誤次數，`0x17` 回傳當前故障位元，`0x14` 回傳累計運轉秒數；均不包含事件歷史時間。

## 每筆建議保存的內容

- 事件序號 + `event_type`（短路／低壓／過壓／過載／位置回授／學習／輸入錯誤等）
- `errBit0`, `errBit1`
- 發生時的電流、相對位置、控制模式、感測器類型
- MCU 上電運行秒數（relative uptime；沒有 RTC 不可稱為日期時間）及 `MotorCNT`
- FW 版本、重啟原因、資料校驗資訊與 schema version

## 建議的事件儲存策略

- 偵測「無錯 → 有錯」或故障位元變化時記錄一次；連續同一故障**不要每控制週期都寫 Flash**。
- RAM 中累積事件；採有 wear leveling 的 Flash 事件環形佇列，或低寫入成本的 FRAM/EEPROM。資料區不能與 bootloader、程式區、現有 0x0800E800 / 0x0800F000 參數槽衝突。
- 釐清斷電保存的最低電壓與 hold-up 能量，並對斷電寫一半等情況以 CRC、版本號與 commit marker 做復原。
- 推薦新增唯讀命令如 0x32（讀事件數與能力）及 0x33（分頁讀事件）。命令碼**只是待定建議**，不可直接視作現行 Protocol。
- 清除歷史紀錄應使用獨立權限與明確確認，且不得被「清除當前故障」意外清掉。

## 導出檔

等韌體支援後，PC Tool 可依序讀出所有事件，輸出 JSON/CSV；現階段 v0.7 的 `CI76_Diagnostic_*.json` 只有目前狀態與故障次數，不包含離線事件歷史。
